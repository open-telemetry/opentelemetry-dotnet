# OpenTelemetry .NET Diagnostic: OTEL1006

## Overview

This is an Experimental API diagnostic covering the following APIs:

* `ProcessContextOptions`
* `ProcessContextPublisher`
* `TracerProviderBuilder.AddProcessContext` extensions
* `MeterProviderBuilder.AddProcessContext` extensions
* `LoggerProviderBuilder.AddProcessContext` extensions

Experimental APIs may be changed or removed in the future.

## Details

The OpenTelemetry Specification is adding [Process Context
Sharing](https://github.com/open-telemetry/opentelemetry-specification/pull/5370)
(based on [OTEP
4719](https://github.com/open-telemetry/opentelemetry-specification/blob/main/oteps/profiles/4719-process-ctx.md))
at Alpha status. It lets an SDK publish its resolved `Resource` in a named
memory mapping (`OTEL_CTX`) so that out-of-process readers on the same Linux
host, such as the OpenTelemetry eBPF Profiler, can attach the same
`service.name`, `service.instance.id` and other resource attributes to the
telemetry they collect.

We are exposing these APIs experimentally for the following reasons:

* The specification is not merged yet and is marked Alpha. The header format,
  the publication and update protocol, and the configuration
  (`OTEL_EXPERIMENTAL_PROCESS_CONTEXT_ENABLED`) may still change.

* The specification says that additional, non-resource attributes may be
  published alongside the resource. The first expected user is thread context
  sharing ([OTEP
  4947](https://github.com/open-telemetry/opentelemetry-specification/blob/main/oteps/profiles/4947-thread-ctx.md)),
  which is still being designed. The shape of the API for supplying those
  attributes may need to change once that work lands.

* Where the feature should live (the SDK itself or a separate package) has not
  been decided.
